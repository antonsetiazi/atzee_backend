ROADMAP :

SESSION CORE-1 — Authentication Foundation
    Target:
        Membuat /api/auth/* hidup dan stabil.
    Scope:
        core/users
        JWT / token-based auth
        Login API yang sedang kamu panggil
    Deliverables:
        POST /api/auth/login
        POST /api/auth/logout
        GET /api/auth/me
        Refresh token (optional tapi disarankan)
    Output:
        Frontend LoginForm resmi hidup
        Session store frontend terisi real data

SESSION CORE-2 — Tenant Boundary (WAJIB)
    Scope:
        core/tenants
        User ↔ Tenant relation
        Active tenant switching
    API:
        GET /api/tenants
        POST /api/tenants/switch
        GET /api/tenants/current
    Middleware:
        X-Tenant-ID atau token-bound tenant
        Semua request harus dalam konteks tenant
    Output:
        TenantSwitcher frontend hidup
        Semua data isolated per tenant

SESSION CORE-3 — Role & Access Level Engine
    Scope:
        core/roles
        Access level global (viewer → superadmin)
        Role per tenant
    API:
        GET /api/roles
        POST /api/roles
        PUT /api/roles/:id
    Output:
        Frontend bisa render menu berdasarkan role
        Tidak ada hardcode permission di frontend

SESSION CORE-4 — Permission Engine
    Scope:
        core/permissions
        Permission resolver
        Policy check
    API:
        GET /api/permissions/me
        POST /api/permissions/check
    Konsep:
        Permission = (app, resource, action)
        Role → permission mapping
        User override (optional)
    Output:
        Frontend core hanya baca schema
        Semua logic akses di backend

SESSION CORE-5 — Menu & UI Schema Provider
    Scope:
        UI schema generator
        Menu tree per role & tenant
    API:
        GET /api/ui/menu
        GET /api/ui/schema
    Output:
        Frontend 100% dynamic
        Vertical bisa nambah menu tanpa ubah core

SESSION CORE-6 — Global & Tenant Settings
    Scope:
        core/settings
        Global vs tenant-scoped settings
    API:
        GET /api/settings
        PUT /api/settings
    Use case:
        Branding
        Feature flag
        Accounting rules

SESSION CORE-7 — Audit Log & Activity
    Scope:
        core/audit_logs
        Auto logging via middleware
    Data:
        user
        tenant
        action
        resource
        timestamp
        before/after (optional)
    Output:
        Compliance ready
        Debuggable system

SESSION CORE-8 — Notification Kernel (Optional tapi strategis)
    Scope:
        core/notifications
        In-app notification
        Event-based

SESSION CORE-9 — Hardening & Contract Lock
    Fokus:
        API versioning (/api/v1)
        Error standardization
        Permission edge cases
        Tenant isolation test
    Output:
        ✅ CORE DIKUNCI
