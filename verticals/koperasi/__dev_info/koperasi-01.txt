🎯 TUJUAN VERTICAL KOPERASI
=========================================
    Vertical ini harus:
        - Bisa dipakai koperasi simpan pinjam
        - Bisa dipakai koperasi serba usaha
        - Bisa dipakai koperasi produksi
        - Multi-tenant
        - Bisa diskalakan 5–10 tahun
        - Cukup fleksibel untuk regulasi Indonesia


🧠 DEFINISI DOMAIN KOPERASI
=========================================
    Koperasi punya karakteristik unik:
        1. Ada anggota (member)
        2. Ada simpanan
        3. Ada pinjaman
        4. Ada SHU (Sisa Hasil Usaha)
        5. Ada RAT (Rapat Anggota Tahunan)
        6. Kepemilikan berbasis anggota
        7. Modal berasal dari anggota

    Berbeda dari perusahaan biasa.


🏗 STRUKTUR LAYER (SESUI ARSITEKTUR ATZEE)
=========================================
| Layer              | Isi                                   |
| ------------------ | ------------------------------------- |
| Core               | Auth, Tenant, Role Engine             |
| Business           | Ledger, Journal, Transaction, Partner |
| Vertical: Koperasi | Member, Savings, Loan, SHU, RAT       |



📦 FITUR UTAMA VERTICAL KOPERASI
=========================================
    1. Manajemen Anggota (Member Management)

        Fungsi:
            - Registrasi anggota
            - Status (aktif / nonaktif / keluar)
            - Nomor anggota otomatis
            - Data KTP, alamat, kontak
            - Tanggal masuk
            - Simpanan wajib default

        Backend:
            - CoopMember
            - Relasi ke Partner (business layer)
            - Relasi ke ledger account otomatis


    2. Simpanan (Savings Engine)
        Jenis simpanan:

        | Jenis              | Wajib?       | Bisa ditarik? |
        | ------------------ | ------------ | ------------- |
        | Simpanan Pokok     | Ya (1x)      | Tidak         |
        | Simpanan Wajib     | Ya (bulanan) | Tidak         |
        | Simpanan Sukarela  | Tidak        | Ya            |
        | Simpanan Berjangka | Opsional     | Sesuai tenor  |


        Engine harus bisa:
            - Auto-generate transaction
            - Post ke ledger
            - Tracking saldo per anggota
            - Bunga opsional

        Backend:
            - CoopSavingsAccount
            - CoopSavingsTransaction

        Menggunakan:
            - Business → Transaction Engine
            - Business → Ledger Posting


    3. Pinjaman (Loan Management)
        Fitur wajib:
            - Pengajuan pinjaman
            - Approval workflow
            - Plafon limit per anggota
            - Tenor
            - Bunga flat / efektif
            - Jadwal angsuran
            - Denda keterlambatan
            - Pelunasan dipercepat

        Backend:
            - CoopLoan
            - CoopLoanInstallment
            - Integrasi ke:
                - Business Journal
                - Business Payment Engine


    4. SHU (Sisa Hasil Usaha)
        Ini yang membuat koperasi unik.

        SHU dihitung berdasarkan:
            - Jasa Modal (simpanan)
            - Jasa Usaha (transaksi anggota)
            - Cadangan
            - Dana sosial

        Vertical harus bisa:
            - Hitung SHU otomatis dari ledger
            - Distribusi ke anggota
            - Posting jurnal pembagian SHU

        Backend:
            - CoopSHUPeriod
            - CoopSHUDistribution


    5. RAT (Rapat Anggota Tahunan)
        Fitur:
            - Generate laporan tahunan
            - Rekap SHU
            - Rekap anggota
            - Voting opsional
            - Notulensi

        Tidak perlu logic kompleks.
        Cukup sebagai workflow + reporting.


    6. Modul Usaha (Opsional)
        Jika koperasi punya:
            - Unit toko → pakai Vertical POS
            - Unit produksi → pakai Vertical Manufacturing
            - Unit distribusi → pakai Vertical Distributor

        Vertical Koperasi tidak menggantikan vertical lain.
        Dia hanya:
            Menjadi “governance & member layer”.

🧠 STRATEGI ARSITEKTUR (SANGAT PENTING)
=========================================
    Vertical Koperasi:
        ❌ Tidak buat ledger sendiri
        ❌ Tidak buat payment engine sendiri
        ❌ Tidak buat auth sendiri
        ❌ Tidak tahu UI

    Dia hanya:
        Menyusun aturan koperasi di atas business engine
